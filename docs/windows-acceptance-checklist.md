# Windows 实机验收清单（DPAPI 凭据后端）

面向用户的 Windows 实机验收。逐项勾选；任何一项不符即为验收失败，附现象回报。

前置：Windows 10/11 桌面版，本地标准账户登录，使用发布构建的 `server.exe`
（或 `go build` 产物）。凭据文件为**主数据库同目录**下的 `secret.db`。

## 1. 登录即用（UX 红线）

- [ ] 首启 → 设置 → AI / LLM 填写 API Key → 保存成功。
- [ ] **重启整个机器** → 解锁登录 → 直接启动应用并进入 AI GTD / 备份页，
      **无需任何口令、授权或弹窗**即可使用。
- [ ] 运行中强杀 `server.exe` 进程 → worker 重启后取 LLM key 成功
      （随手记任务照常拆解），全程零输入。

## 2. 凭据后端展示

- [ ] 设置页凭据状态区显示后端为「**Windows 账户级凭据保护**」；
      `GET /api/credentials/status` 返回 `backend == "windows-dpapi"`。

## 3. 跨账户拷贝 → 拒绝解密 → 重置恢复（不锁死）

DPAPI blob 绑定当前 Windows 账户，跨账户/跨机不可解——这是特性不是缺陷。
验收其恢复路径：

- [ ] 在账户 A 下配好凭据、确认状态可用后登出；新建并登录第二个本地标准账户 B。
- [ ] 把 A 的 `secret.db` 拷入 B 使用的程序数据目录（与 B 的主数据库同目录），
      启动应用：凭据状态接口/设置页报 **unavailable（凭据不可用）**，
      应用其余功能不崩溃，B 侧任何操作都拿不到 A 的凭据明文。
- [ ] 在设置中点击「重置凭据」→ 返回成功（HTTP **204**），页面提示凭据已重置。
- [ ] 重新配置 LLM key → 状态恢复 `windows-dpapi` 可用。
- [ ] 全过程**不出现 500 锁死**（重置按钮不可点、状态接口持续 5xx 均算失败）。

## 4. 篡改防护口径（如实，不夸大）

- [ ] 用十六进制编辑器直接改动 `secret.db` 中密文区（blob 末段，含 HMAC 的
      最后 16 字节）任意一字节 → 重启应用即拒绝读取该 blob，状态报
      unavailable；改回原字节则恢复正常。
- [ ] 对 blob 其余部位（头部元数据区）的单字节翻转：应用要么报错拒读，
      要么解出与原明文**逐字节相同**的结果。
      即真实不变量是——**凭据明文内容不可能被静默改写**；
      不承诺「任意 1 字节篡改必然拒绝」。

## 5. 上古安装（v1 遗留数据）提示口径

- [ ] 磁盘上只有 v1 时代遗留的 `secret.db`（文件头魔数为 `LTMSECv1`）：
      启动日志给出且仅给一行提示
      「检测到不再支持的 v1 凭据文件,请在设置中重置凭据」；
      应用不退出、不自动删文件，用户在设置中重置后恢复正常。
- [ ] 磁盘上**没有** v1 `secret.db`、只有 settings 表中的旧密文列
      （`backup_config` 的 `*_encrypted` 列）：启动**无任何提示**，
      这是预期行为。如实认知边界：旧列数据已无读取方，执行过一次
      「重置凭据」后即不可达，无法再找回其中内容。

## 6. 平台范围说明

- [ ] 本期范围：**Windows 为新增支持**；macOS 暂不在发布目标内
      （Keychain 后端另开 issue，见后续计划）；Linux / Android 行为不变
      （Secret Service / Android Keystore 各自路径无任何改动）。
