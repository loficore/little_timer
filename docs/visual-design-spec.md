# 视觉设计规范（可执行红线）

> 状态：v1 —— 全部 7 页（dark + light）、三个主要弹窗（HabitModal / WallpaperModal / MasterPasswordModal）、移动端 390/412 均已截图诊断（2026-10）。
> 诊断方法：起 vite dev server 截真实页面，逐条对照本文红线，而不是凭感觉改。
> 诊断截图存放于仓库根 `design-audit/`（已 gitignore，本地工作产物不入库）；重诊断后旧图可直接覆盖。

## 总策略

- **dark 是主版本**：主角（发光数字盘）已成立；light 按 dark 的对比度水准重做，而不是各自演化。
- 每套主题必须有且只有一个**视觉锚点**（dark：辉光数字盘；light：待定，倾向纸质纹理 + 大号计时盘），其余元素降对比为锚点让路。
- 改动优先级：① 色彩红线（R1/R2）→ ② 页面骨架（R3~R5）→ ③ light 主题重做。

## R1 交互元素对比度红线（最高优先级）

**问题**：primary 按钮（timer「选择习惯」、habits「+添加」、schedule「运行调度」、dailySweep「立即扫一遍」）白字压中彩度紫，dark / light 两套主题下均近乎不可读。根因不是主题补丁，是 `--my-primary-container`（25% 透明紫 + 浅字）被错误复用到了实底按钮上——primary 的容器形态与按钮形态没有分开定义。次级证据：aigtd 提交箭头按钮同样灰到近乎隐形。

**规则**：
- 所有可交互元素（按钮、输入框、导航项、开关）的文字/图标对其底色对比度 **≥ WCAG AA**（正文 4.5:1，大字/图标 3:1）。
- 反例佐证规则可行：设置页「保存设置」在 dark 下是实底紫 + 可读白字——说明 solid 形态存在，只是各页 primary 按钮随机选用形态。统一走 solid 即可，无需新发明。
- primary 拆成两个 token，禁止混用：
  - `--my-primary-solid`：实底 + 高对比字，用于按钮；
  - `--my-primary-container`：低透明底 + 浅字，只用于数字盘、徽章等装饰性容器。
- **验收**：写进 VRT——Playwright 截图后对按钮区域采样计算对比度，低于阈值即 fail。不靠人眼把关。

## R2 层级色彩语法红线

**问题**：区块标题（「习惯集」「调度」「任务评分」、AIGTD 页的「AI GTD」）在两套主题里都被映射到 `--my-on-surface-variant` 一类弱化色，比正文还灰；同时 primary 色相在数字、圆点、按钮容器三种身份间无规则游走。**stats 页是集中爆发点：同一屏并存两套"主色"——筛选 pill / 环形图用长春花紫，指标数字「0时 1分」「1」用亮蓝，互相打架**，证明 primary 用法完全没有语法。

**规则**：
- 定 5 级排版阶梯，每级绑定 token，全页面统一：

  | 级别 | 用途 | 色彩 |
  |---|---|---|
  | T1 | 顶栏页名 | `on-surface` 满对比 |
  | T2 | 页/区块标题 | `on-surface` ≥90% 对比，**禁止用 variant 色** |
  | T3 | 正文 | `on-surface` ~85% |
  | T4 | 辅助说明 | `on-surface-variant` |
  | T5 | 占位/禁用 | variant 再降，且不可承载信息 |

- primary 色相只允许三种角色，按角色用 token、不许直接引色值：数字盘内容（锚点）、交互态（focus/active 描边）、数据点缀（圆点/徽章）。**按钮实底除外**（走 R1 的 solid）。
- 图表/数据可视化色（环形图分段、指标数字、pill 选中态）走独立的 `--my-data-*` 序列，**不得与 primary 同色相抢锚点地位**；一屏内数据色不超过一个主色相 + 辅助明度阶梯（stats 页长春花紫 pill + 亮蓝数字并存即违规）。
- 用户可选的数据色板（HabitModal 的 10 色圆点）同样收编进 `--my-data-*`：现为全饱和彩虹色 + 原生 hex 输入框，与任何主题色板脱节，即反例。
- 任何不在 token 表内的色值出现在组件里（如 daisy 默认 `--p` 漏进来）视为 bug。

## R3 页面骨架统一

**问题**：无页面级布局系统。timer 内容浮在上 1/3、下方约 400px 真空；habits 单卡孤悬；settings 巨型空卡里只躺一个控件。每页列宽、对齐、留白节奏各异，观感是「没摆完的桌子」。

**规则**：
- 所有内容页套同一骨架：`页标题区(T2) → 主内容区 → 底部操作区`，列宽与左右边距由 layout token 统一（现有 `--layout-px` 扩展为完整栅格）。
- 垂直节奏用固定档位（现有 `--spacing-*`），禁止组件内写死 `mb-6 sm:mb-7` 式的自由间距。
- 内容不满一屏时，主内容区要么垂直居中，要么由空态占据——不允许「顶部堆叠 + 底部真空」。

## R4 空态即首页

**问题**：habits「1 个习惯孤卡 + 全屏空白」、schedule「暂无任务」小字躺在网格中间；dailySweep 提示语浮在上 1/3、下方整屏真空；AIGTD 的「空空如也 —— 写点什么吧」有文案但在虚线框内右错位、无 CTA。空数据是这类工具的常态，现在的空态让产品看起来像坏了。

**规则**：
- 每个列表/网格页必须设计空态：一句说明 + 一个引导 CTA（如「还没有习惯集，先创建一个」），CTA 走 R1 的 solid 按钮。
- 空态占主内容区，不允许元素孤悬在版面一角。

## R5 标题语法唯一

**问题**：同为页级标题存在至少五种写法——顶栏居中深色「专注」、内容区左对齐灰字「习惯集/调度/AI GTD」、另一种灰度「任务评分」、辉光到发虚的「每日回顾」、以及 stats 干脆没有内容区标题。

**规则**：
- 顶栏 T1 与内容区 T2 的分工写死：顶栏只放页名；区块头一律 T2 左对齐；禁止组件自创第六种样式。
- 标题禁止叠加装饰性辉光/blur（「每日回顾」的辉光把字糊掉即反例）；辉光只属于主题锚点（数字盘）。
- 本条与 R2 阶梯表一起作为 VRT 基线重生成（`test:vrt:update`）前的审查清单。

## R6 移动端断点完整性

**问题**（390/412 截图实证）：
- schedule 390px 下时间轴 24 个刻度挤成重叠乱码（`06:0007:0008:00…`），信息完全不可读；
- 设置页 7 个 tab 横向溢出，两端被裁切且无滚动/溢出指示；
- 移动端 timer 页内容堆在上 1/4，底部导航上方约半屏真空（R3 的移动端放大版）。

**规则**：
- 390px 是受支持断点：任何刻度/标签类元素在 390px 下必须实测不重叠（时间轴改为抽样刻度 + 滚动，或纵向布局）。
- 横向溢出的导航（tab bar）必须显式可滚动并带渐隐指示，禁止静默裁切。
- 移动端每页同样执行 R3 骨架：内容不满屏时垂直居中或由空态占据。

## R7 弹窗系统统一

**问题**：三个弹窗三套语法——HabitModal 无关闭按钮、内容超屏被硬裁切（壁纸选择区露半截）且 Escape 无效；WallpaperModal 有 X 和 header 分隔线，但「渐变」tab 缺失、「取色器」渲染成未设样式的小方块；MasterPasswordModal 尺寸克制、按钮可读（正面样例）。

**规则**：
- 所有弹窗共用一个壳组件：header（T2 标题 + X）、内容区（超高时内部滚动，禁止裁切）、footer（取消/确认，确认走 R1 solid）。
- Escape 关闭 + 遮罩点击关闭为默认行为，逐弹窗豁免需写明理由。
- 弹窗宽度、圆角、层级（z-index）、遮罩透明度由 token 定义，禁止组件各写各的。
